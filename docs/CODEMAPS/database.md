# Database & Domain Models — Codemap

**Last Updated:** 2026-04-13

## Overview

All data storage is in-memory. The system uses Pydantic v2 models for type safety and validation. No persistent database is currently used (suitable for demo/MVP; Phase 3 will add PostgreSQL persistence).

---

## Core Models

### Session

**File:** `src/domain/models/session.py`

```python
class Session(BaseModel):
    session_id: str = Field(default_factory=lambda: str(uuid4()))
    user_id: str | None = None
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
    updated_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
    
    # Session state
    turn_count: int = 0
    confirmed: bool = False
    selected_bundle_key: str | None = None
    auth_token: str | None = None
    
    # Pipeline state (accumulated across turns)
    accumulated_extraction: ExtractionResult | None = None
    latest_classification: ClassificationResult | None = None
    latest_recommendation: RecommendationResult | None = None
    clarification_turn_count: int = 0
    
    # User hints (Lars scenario support)
    preselected_intent: str | None = None           # User's chosen use-case
    preselected_bundle_key: str | None = None       # User's pre-selected bundle
```

**Lifecycle:**
1. Created by `POST /sessions` → initial state all None/False/0
2. Each `POST /reply` increments `turn_count`, updates `accumulated_extraction`, `latest_classification`, `latest_recommendation`
3. `POST /confirm` sets `confirmed=True` and `selected_bundle_key`
4. `POST /preview` uses `selected_bundle_key` and `accumulated_extraction` if available
5. Deleted when session expires (no automatic cleanup currently; Phase 3 will add TTL)

**Key Fields:**
- `confirmed` — Gate for `POST /preview` (confirmed route only)
- `selected_bundle_key` — Output of bundle classification, set by user confirm
- `accumulated_extraction` — Merged across all turns by ConversationFlow
- `latest_classification` — Latest classification result (for early preview bundle resolution)
- `preselected_intent` — Passed to preview pipeline for workflow_hints
- `preselected_bundle_key` — Used in early preview fallback chain (Lars scenario #1)

### ClassificationResult

**File:** `src/domain/models/classification_result.py`

Output of bundle classification (Dev A's Interpreter). Updated per turn.

```python
class ClassificationResult(BaseModel):
    session_id: str
    selected_bundle: BundleSuggestion | None = None  # Top prediction
    ranked_candidates: list[BundleSuggestion] = Field(default_factory=list)
    confidence_status: Literal["proceed", "suggest_alternatives", "clarify", "fallback_generic"]
    top_confidence: float  # 0.0-1.0
    score_gap: float  # Confidence gap between top 2 candidates
    missing_context: list[str] = Field(default_factory=list)  # What to clarify
    reasoning: str  # Explanation of classification
```

**BundleSuggestion:**
```python
class BundleSuggestion(BaseModel):
    bundle_key: str  # e.g. "hr_management"
    display_name: str
    confidence: float
    reasoning: str
    matched_signals: list[str] = Field(default_factory=list)
```

**Confidence Status Interpretation:**
| Status | Meaning | Next Action |
|--------|---------|------------|
| proceed | High confidence (>0.8) | Show preview with selected bundle |
| suggest_alternatives | Medium confidence (0.6-0.8) | Show selected + alternatives |
| clarify | Low confidence (<0.6) or ambiguous signals | Ask follow-up question |
| fallback_generic | No clear signal | Use generic bundle |

**Used By:**
- Replier: generates clarification questions based on `missing_context`
- Early preview: fallback chain uses `top_confidence >= 0.6` check

## Data Flow Diagram

```
User Request
    ↓
SessionRepository.get(session_id)
    ↓ (returns Session)
ConversationRepository.get_messages(session_id)
    ↓ (returns list[ConversationMessage])
ConversationFlow.process_turn(session_id, message)
    ├─ InterpreterService.classify()
    │   ↓ returns ClassificationResult
    │   → SessionRepository.update() [latest_classification]
    ├─ ReplierService.generate_reply()
    │   ↓ returns assistant_text
    └─ ConversationRepository.add_message(session_id, turn_number, "assistant", text)
    └─ SessionRepository.update() [accumulated_extraction, latest_recommendation]
    ↓
PreviewFlow.run(session_id, bundle_key, conversation_history)
    ├─ ConversationRepository.get_messages()
    ├─ PreviewGeneratorService.generate()
    │   ├─ BundleCatalog.get(bundle_key)
    │   ├─ 7-node pipeline [all data structures from PreviewGeneratorState]
    │   ↓ returns (generation_json, dummy_data_json)
    └─ AppPayload assembly
    ↓
AppPayloadResponseSchema (JSON response)
```

## In-Memory Storage Characteristics

| Store | Capacity | Lookup | Update | Cleanup |
|-------|----------|--------|--------|---------|
| SessionRepository | Unbounded | O(1) by session_id | O(1) | Manual (no TTL) |
| ConversationRepository | Unbounded | O(1) by session_id | O(1) | Manual (no TTL) |
| BundleCatalog | Fixed (~15 bundles) | O(1) by bundle_key | N/A (read-only) | N/A |

**Phase 3 Considerations:**
- Migrate to PostgreSQL for persistence
- Add session TTL (e.g., 24 hours)
- Archive old conversations
- Index by user_id for multi-session queries

## Validation

All models use Pydantic v2 validators:

```python
@field_validator("selected_bundle_key")
def validate_bundle_key(cls, v: str) -> str:
    if v not in VALID_BUNDLES:
        raise ValueError(f"Unknown bundle: {v}")
    return v
```

**Custom Coercion:** `Session._coerce_latest_classification()` handles legacy payload shapes (backwards compatibility).

## Testing

**Fixtures:**
- `mock_session` — Session with reasonable defaults
- `mock_conversation` — Session with 3-turn conversation history
- `mock_bundle_catalog` — In-memory catalog with 5 test bundles

**Example Test:**
```python
def test_session_accumulates_extraction():
    repo = SessionRepository()
    session = repo.create()
    
    # Simulate turn 1
    extraction1 = ExtractionResult(company_name="Acme")
    session.accumulated_extraction = extraction1
    repo.update(session)
    
    # Simulate turn 2
    extraction2 = ExtractionResult(company_name="Acme", employee_names=["Alice"])
    session.accumulated_extraction = extraction2
    repo.update(session)
    
    # Verify
    updated = repo.get(session.session_id)
    assert updated.accumulated_extraction.employee_names == ["Alice"]
```

## Serialization

All models support `.model_dump()` for JSON serialization:

```python
session.model_dump()  # → dict[str, Any]
session.model_dump_json()  # → JSON string
```

FastAPI automatically calls `.model_dump()` for response schemas, so no manual serialization needed in endpoints.
